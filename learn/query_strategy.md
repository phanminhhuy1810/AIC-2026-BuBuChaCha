# Query notes for the search prototype

The CLIP mode encodes a text query, normalizes its vector, and searches normalized keyframe vectors with FAISS inner product similarity. It returns similar images; it does not answer a question about them.

## Writing a CLIP query

Treat wording choices as experiments and inspect the returned frames:

- Start with a short description of the visible subject and action, such as `a person riding a motorcycle`.
- Add a useful visual detail when the first results are too broad: `a person riding a yellow motorcycle on a busy street`.
- Describe visible evidence. For example, try `a woman covering her face` when that action matters more than an inferred emotion.
- Try another description of the same scene if the results miss it: `a street food vendor`, `a person cooking noodle soup at a food stall`, or `a steaming pot beside plastic tables`.

There is no required prefix or fixed query template. A phrase such as `a photo of` is another wording to try, and longer queries are not automatically better. Examples here use English, as in the prototype's search prompt.

## Choosing a search mode

| Evidence to search | Mode | Example |
| --- | --- | --- |
| Visual scene or activity | CLIP | `a family eating at a table` |
| Text visible in a keyframe | OCR | `EXIT` |
| Words in a transcript | ASR | `xin chao` |
| Detected object classes and minimum counts | YOLO | `2 person, car` |
| Descriptions in timestamp order | Temporal | `street scene then temple then sunset` |

OCR, ASR, and YOLO require metadata generated by their corresponding demo scripts. OCR and ASR perform case-insensitive substring searches. YOLO uses detected class labels; `2 person, car` requests at least two people and one car.

The temporal demo searches each description with CLIP and chooses a chain with increasing timestamps. It does not require all selected frames to come from the same video, so inspect multi-video results carefully.

These are separate modes in the interface. There is no automatic score fusion or VQA reranking; `vqa1_demo.py` is a separate script.

## Checking a query

Choose a scene you know is present in your input video, write a description, and inspect the top results. Record the query, returned keyframes, and whether the target appears. This gives a small repeatable check for wording changes; it is not a retrieval benchmark.
